# 스테이지 확장 계획 (M14 후보)

> **확정 (2026-10-06, D-058):** §7 1·2 제안 수용, 걷는 인간 허용, 방 크기는 3배가 아니라 1.5~2배.
>
> 2026-10-05 사람 플레이테스트 피드백 #5: "스테이지가 너무 작다. 짧은 스테이지 방식이라면 스테이지를 많이 찍어 내고, 방해 요소의 종류·배치·해법을 고안해 레벨링해야 한다. 배치와 조합을 더 다각화하자." 사람이 방향을 승인했다("계획을 그렇게 세우자"). 이 문서는 계획이며, 아래 §7 결정 항목을 사람이 확정하면 M14로 시작한다.

## 1. 지금 상태
| 항목 | 현재 |
|---|---|
| 스테이지 | 5개 (거실 2, 침실, 화장실, 베란다) |
| 방 크기 | 거실 500×250×400u, 침실 400×250×400, 화장실 220×250×260, 베란다 450×250×300 |
| 한 판 길이 | 봇 클리어 40~150초 |
| 인간 | 1명, 자리 이동 없음(D-011), 자세 변경까지(D-053) |
| 요소 | 시각·청각·졸음·취함·선풍기 바람·모기향·스프레이(광분)·자동 분사기·거미줄·물방울·습기·증기·은신처·CO₂·흡혈 중 이벤트 3종(M13) |

문제: 방이 좁아 "어디로 접근할지"의 선택지가 적고, 요소가 스테이지마다 한꺼번에 나와 각 요소를 익히고 조합을 푸는 단계가 없다.

## 2. 방향
1. **방을 넓힌다:** 길이·폭 1.5~2배(예: 거실 + 주방이 이어진 약 800×260×650u, D-058). 가구로 구역을 나눠 접근 경로가 2개 이상 생기게 한다. 천장 관망(M13)이 정찰 수단이 된다.
2. **짧은 스테이지를 많이:** 4장 × 5스테이지 = 20개(기존 5개는 장의 일부로 흡수). 한 판 목표 1~3분.
3. **레벨링 원칙**
   - 소개: 새 요소는 한 스테이지에 하나만, 안전한 배치로 처음 보여 준다.
   - 조합: 이미 배운 요소를 2개까지 묶는다.
   - 응용(장 마지막): 해법이 2개 이상인 배치(경로 A/B, 타이밍, 스킬)로 마무리한다.
   - 장마다 "광분을 견디거나 피해야 하는" 스테이지를 하나 둔다(D-057: 신중한 플레이에서는 광분이 드물다). 예: 처음부터 예민한 인간, 자국이 남은 채 시작, 진정 시간이 긴 인간.

## 3. 요소 목록 (위협 → 해법)
| 요소 | 상태 | 위협 | 해법 |
|---|---|---|---|
| 인간 시선·둘러보기 | 있음 | 시야 원뿔 | 시선 반대편, 가구 뒤 |
| 귀(청각) | 있음 | 비행 소음, 대시 | 정밀 비행, 붙어서 기다리기 |
| 졸음 / 취함 | 있음 | 깨는 순간 / 무작위 휘두르기 | 잘 때 접근 / 손 경로 피하기 |

| 모기향 / 스프레이 / 자동 분사기 | 있음 | 중독 | 은신처 회복, 연무 우회 |

반려동물 등 비인간 적은 GOAL 범위 밖이다.

## 4. 장 구성 초안 (4장 × 5)
| 장 | 방 | 1 소개 | 2 소개 | 3 조합 | 4 광분 | 5 응용 |
|---|---|---|---|---|---|---|
| 1 거실 | 넓은 거실·주방 | 조는 인간(튜토리얼) | TV 시선 둘러보기 | 시선 + 선풍기 | 예민한 인간(자국 1개 시작) | 넓은 거실, 경로 2개 |
| 2 침실 | 침실·드레스룸 | 누운 인간 + 모기향 | 조명 스위치 | 모기향 + 조명 | 스프레이 든 인간 | 모기장 + 조명 + 선풍기 |
| 3 물가 | 화장실·주방 | 물방울·습기 | 증기 | 자동 분사기 + 물방울 | 전기 모기채 | 증기 은신 + 분사기 + 시선 |
| 4 베란다 | 베란다·마당 | 취한 인간 | 거미줄 | 두 사람 | 두 사람 중 하나 광분 | 최종: 술자리 전체 |

## 5. 제작 방식
- **스테이지마다 항상 함께 쓰는 문서 (D-062):** 애셋 스펙(`spec/assets` — 새 모델·소품마다 문서 하나, 인덱스의 사용처, 필요한 텍스처·VFX·조명). 스테이지 작업 계획에는 "필요 애셋 목록과 스펙 갱신"이 반드시 들어간다. 모델이 없는 동안은 화이트박스 + 모키 표현 큐(글자)로 대신한다.
- 레벨은 지금처럼 데이터(`data/rooms`, `data/levels`)로 만들고 `LevelValidator`가 검사한다(도망칠 곳 보장 등 spec/07 공통 규칙).
- 스테이지마다 클리어 봇·발각 봇 시나리오와 대표 캡처를 둔다(GOAL D5·D8 확장).
- 넓은 방에 맞춰 봇 경로 도구를 보강한다(장애물을 피하는 경유점 탐색, M13에서 설계 검증 봇에 먼저 넣음).
- 성능: 방이 커지면 형상 수가 늘어난다 → 충돌 질의 공간 분할과 성능 측정(perf)을 함께 본다.

## 6. 함께 바뀌는 것
- GOAL §1 "Title → Stage 1~5 → Ending" → 20 스테이지 흐름, 스테이지 선택 화면은 장별 페이지.
- 저장 데이터: 스테이지 기록 키 확장(기존 기록 유지).
- 혈액 포인트·스킬 비용: 스테이지 수가 늘어난 만큼 다시 맞춘다(spec/09).
- 튜토리얼 안내: 1장 1~2.

## 7. 사람이 정할 것
1. 스테이지 수(제안 20)와 장 구성(§4 초안).
2. 신규 요소 중 넣을 것(제안: 조명 스위치, 모기장, 전기 모기채, 두 사람, 에어컨 타이머).
3. 걷는 인간 허용 여부(D-011 해제 여부).
4. 방 크기(제안: 기존의 2~3배).

## 8. 작업 순서 (확정 뒤)
1. 넓은 방 1개로 기술 검증: 성능, 봇 경로, 카메라·안개 거리.
2. 신규 요소를 Core 규칙 + 테스트로 하나씩 추가한다.
3. 장 단위로 스테이지를 만든다(데이터 → 봇 → 캡처 → 플레이 감각 메모).
4. 경제(포인트·스킬)와 흐름(UI·저장)을 정리한다.
