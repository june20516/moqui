# Gulf of Execution / Evaluation 보완 계획 (M14~, D-062)

> 출발점: 2026-10-06 사람 요청. "하고 싶은 것과 실제 조작 사이"(실행 간극)와 "지금 상태를 알아보기"(평가 간극)를 줄인다.
> 원칙: (1) 규칙을 여러 개 외우게 하지 말고 하나의 개념 모델에서 행동이 나오게 한다. (2) 누르기 전에 무엇이 일어날지 보인다(피드포워드). (3) HUD 글자보다 세계·캐릭터의 반응으로 읽힌다.
> 컨셉: **모키는 규칙상 모기, 보이는 모습은 마법소녀**다. 모기의 기관은 마법소녀의 동작·소품으로 표현한다(`spec/12-moki-cues.md`).
> 모델·애니메이션·VFX가 필요한 표현은 지금 **모키 표현 큐**(작은 글자 이펙트)로 대신하고, 요구는 `spec/assets/`에 스펙으로 남긴다. 큐 ID는 그대로 두고 표시기만 바꾼다.

## 1. 개념 모델: "지팡이를 꽂으면 붙들린다"
흡혈 중 몸 고정, 시선 때 얼기, 부위가 움직일 때 버티기를 **하나의 그림**으로 묶는다.
- 흡혈 버튼을 누르고 있으면 모키가 지팡이(하트 보석)를 피부에 꽂고 있다 → 몸이 붙들린다(이동키를 누르면 당겨졌다 되돌아옴, `wand.tug`).
- 버튼을 놓으면 지팡이를 빼서 품에 안는다 → 자유, 그리고 가만히 있는 상태(`wand.out`, 시선 중이면 `freeze`).
- 부위가 움직일 때 누르고 있으면 지팡이를 꽉 쥐고 버틴다(`wand.grip`), 놓고 있으면 튕겨 난다.
- 대시는 지팡이를 억지로 뽑는 긴급 탈출(`wand.yank`). 대가: 가려움 상승(규칙 변경, 수치 tuning).
- 튜토리얼 문장 하나: "지팡이를 꽂고 있는 동안은 몸이 붙들려요."
- **할 일:** 큐 구현(완료) → 대시 탈출 가려움 대가(Core, 테스트) → 모델 동작(애셋 `moki` 스펙대로).

## 2. 착지: 거리 맞추기 → 다가가면 내려앉기
- 정밀 비행으로 붙을 수 있는 표면에 천천히 닿으면 그대로 내려앉는다(Core 규칙 추가). F는 "가까운 곳에 즉시 앉기"로 유지.
- 피드포워드: 착지 범위 안이면 모키가 발끝을 내밀고 발밑에 마법진 그림자(`land.ready`, VFX 스펙).
- 스냅 활공: F를 누르면 0.15초 동안 그 지점으로 미끄러져 붙는다. 범위 끝에서도 실패 없음.
- 실패도 읽히게: 붙을 수 없는 표면·허공에서 F → `land.miss`(허공을 디딤).

## 3. 맨살과 옷
- 체온 감지를 "맨살이 따뜻하게 숨 쉬듯 일렁임"으로 강화, 옷은 차갑고 무늬 있는 천으로(애셋 `human-adult` 의상 스펙).
- 지팡이 끝이 피부를 향하면 하트 보석이 반짝이며 반응(큐 확장: `wand.aim`, 계획).
- 옷에 꽂으려 하면 `wand.cloth`(천을 긁고 미끄러짐) — 구현.

## 4. 3D 거리감
- 이중 그림자: 중력 방향 그림자 + 가장 가까운 표면 그림자(가까울수록 진하게). 마법소녀다운 반짝이는 원형.
- 지면 효과: 표면 가까이 날면 날갯바람에 먼지·솜털·천 주름이 흔들림(VFX 스펙 `vfx-wind-dust` 변형).
- 초점: 조준점이 가리키는 표면에 얕은 심도 초점.

## 5. 비행 조작 체계
- "호버"(현재) / "자유 비행"(W = 보는 방향, 위아래 포함) 두 방식을 정식 설정으로. 1장 첫 스테이지에서 체험 후 선택.
- 대시: 입력이 없으면 무작위 대신 보는 방향. 1인칭에서는 대시 가능 시 방향 표식.

## 6. 소리
- 내 소리: 일반 비행 = 날개 흐림·윙 소리 큼, 정밀 = 날개 반쯤 접힘·소리 작음·가장자리 조용히 어두움(`precise`).
- 인간의 귀: 내 소리가 들리면 귀가 움찔·고개가 기욺(인간 모델 스펙), 모키는 `heard`.

## 7. 누가 어디를 보나
- 인간마다 머리 위 경계 눈(세계 공간), 화면 밖이면 가장자리에 그 사람 색으로.
- 고개를 돌리기 직전 숨·목 소리, 눈동자 방향이 보이게(인간 모델 스펙: 눈동자 본).
- 시선 이벤트에서 인간 얼굴로 카메라 초점이 잠깐 끌림.

## 8. 환경을 미리 읽히게 (조명과 연결, `spec/assets/lighting.md`)
- 빛 웅덩이와 어둠으로 "보이는 곳 / 숨는 곳"을 미리 읽힌다: 분위기 조명은 은신처 안을 직접 비추지 않는다(조명 스펙 §1). 기믹 램프도 같은 툰 추가 조명으로 실제 빛 경계를 만든다(셰이더 수정으로 해결, M14).
- 조명: 켜지기 전 팔이 스위치로 뻗는 동작 + 딸깍, 켜지면 실제 빛 경계, 은신처 푸른빛이 빛에 씻겨 사라짐.
- 에어컨: 켜지기 1초 전 송풍 날개 열림 + 모터 소리, 켜진 동안 먼지 흐름.
- 선풍기: 원뿔 안 먼지 줄기. 모기장: 틈은 실제로 끊긴 그물 + 나풀거리는 실밥, 빠르게 다가가면 그물이 출렁(예고).

## 9. 물방울 탈출
- 숫자 대신 물방울 막이 진행도: 누를 때마다 늘어나고 얇아지다 터짐. 리듬이 맞으면 더 크게 늘어남.

## 10. 왜 들켰나
- 광분 진입 순간 0.5초 느린 화면 + 인간 얼굴 + 원인(눈·귀·가려움·시선) 한 번.
- 결과 화면에 경계 타임라인(원인별 색).

## 11. 플레이 검증 변수 구조 (구현 M14, D-065)
- **대상:** `data/playtest-keys.json`(그룹 6개: 비행, 카메라·조작, 흡혈·흡혈 중 이벤트, 인간 감각, 움직임, 모기 감각·조명 — 키·슬라이더 범위). `spec/tuning.md` "체감 검증 대상"에 같은 목록(테스트가 일치 검사).
- **겹:** `tuning.json` 위에 `playtest.json`(저장 데이터 폴더 `Application.persistentDataPath`)을 덮어쓴다. 목록 밖 키는 거부하고 로그에 이유. 덮어쓴 키는 시작 로그와 화면 왼쪽 위 "플레이 검증 값 N개 적용 중 (F10)". 배치 모드(자동 테스트·캡처·성능)에서는 적용하지 않는다.
- **패널(F10, 스테이지 중):** 열면 일시정지. 그룹 탭, 키마다 −/+(범위의 1/20씩, 범위 안), 기본, 모두 기본값, 프리셋 A/B 저장·불러오기, 저장하고 다시 시작(새 값은 스테이지를 다시 열 때 적용 — 시뮬레이션 설정이 시작 시 고정되므로 반쯤 바뀐 상태를 만들지 않는다). 저장할 때 `playtest-log.jsonl`에 시각·스테이지·바뀐 값(이전→이후).
- **확정:** 에디터 메뉴 Moqui/Playtest/정본으로 올리기 → `tuning.json`·`spec/tuning.md` 해당 줄만 고치고 덮어쓰기를 비운다. 이어서 `Tools/run-tests.ps1`(문서·json 일치, 봇 회귀) 후 커밋. "덮어쓰기 지우기", "파일 폴더 열기"도 있다.

## 12. 자연스러운 움직임 (평가 간극: 몸이 "살아 있다"는 신호)
움직임이 선형이면 "언제 멈추고 언제 돌아볼지"를 몸에서 읽을 수 없다. 실제 몸처럼 관성을 주면 출발·정지 직전의 변화가 예고가 된다.
- **구현 (M14):** 머리 회전 가감속(Core `HeadController.Ease`, `head.turnAccelTime` 0.25s, 넘침 없음), 걷기 가감속·미끄러지듯 멈춤·걸음 출렁임(`human.walkAccelTime` 0.5s, `human.walkBob` 2.5u, 판정 형상도 함께 움직임), 호흡에 맞춘 몸통 부풂·눈 깜빡임(졸면 감음, 표현 전용), 모키 정지 비행 둥실거림(속도가 빠를수록 줄어듦, 표현 전용).
- **다음:** 고개를 돌리기 전 눈동자가 먼저 가는 시선 선행(인간 모델 눈동자 본, §7과 연결), 팔 공격의 예비 동작 곡선, 모키 날개 박자의 속도 연동(애셋 `moki`). 수치는 §11 플레이 검증 변수로 노출한다.

## 13. 조명 디테일 (`spec/assets/lighting.md`)
- **구현 (M14):** 방 데이터 `lights`(표현 전용) → Core `RoomLightDefinition` → Unity `RoomLightingView`. TV는 장면 컷마다 밝기·색이 바뀌고 화면 형상이 같은 빛으로 빛남, 스탠드·복도·협탁은 백열등의 느린 숨, 화장실 형광등은 드물게 끊김, 휴대폰은 스크롤 빛, 베란다는 도시 불빛에 지나가는 차·등불 일렁임, 달빛은 창살 쿠키(텍스처 전까지 절차 쿠키)와 그림자. 툰 셰이더가 추가 조명을 받지 못하던 문제를 고침(Forward+ 루프, 1u ≈ 1cm 규모에 맞춘 범위 감쇠, 셀 단계).
- **애셋 요구:** 창살·블라인드 쿠키, TV·휴대폰 발광 플립북, 갓·한지 투과, 창밖 도시, 달빛 빛줄기 VFX(`vfx-light-shaft`), 캠핑 등불 모델(`veranda-lantern`) — 모두 애셋 인덱스에 등록.
- **다음:** 약한 블룸, 방별 환경광 색, 휴대폰 빛을 손 소켓으로(얼굴을 아래에서 비춤), 흡혈 중 지팡이 하트의 분홍 빛(`wand.drink`), 기믹 조명 켜짐 예고(§8).
